01 The headline

The session opened by installing the Superpowers plugin, then turned to the real objective: finishing the Grant Scout module — the discovery arm of GrantNova (formerly GMAS) that hunts for grants, gathers intelligence, evaluates fit, and reports back to the user. No paid AI, fully deterministic, human-in-the-loop throughout.

Work ran as an orchestrated plan of six work packages, each gated on runnable acceptance criteria. Every "done" was proven by re-running a command and reading its output — never by trusting a claim. The result: the module is built, 174 tests pass, and the database is — for the first time — genuinely migration-controlled.

03 How "done" was proven

Acceptance criteria → runnable VERIFY command → orchestrator re-runs it

Every requirement carried an acceptance criterion ending in a command that produces observable output (a specific pytest run, an alembic check, a row-count parity query). A task counted as done only when that command was re-run and its output read — a direct answer to the standing rule that subagents can hallucinate. Discovery of this session's one real infrastructure bug came straight out of that discipline.

04 The bug the migration workout uncovered

The live database was never actually under Alembic

The app built its schema with create_all(), not migrations — so the real gmas.db had no alembic_version table and was missing the entire discovered_candidates table the Scout depends on. Models and migrations were two sources of truth that had already drifted. The rename became the fix: back up → rebuild a canonical DB from the 001→004 chain → copy the real data across (32 funders, 14 templates, 1 org, 1 criteria) with verified parity → retire the old file. A permanent drift-guard test now fails if models and migrations ever diverge again.

06 What the Scout does

Four phases, each a small deterministic component the orchestrator wires together — no paid AI anywhere in the path.

Hunt

Find opportunities

grants.gov API, keyless web search, funder-site sweeps and public portals; the org profile expands into up to 40 deterministic queries for a "search everywhere" run.

Gather

Collect intelligence

A polite fetcher honors robots.txt, rate-limits per host, and caches to disk; a rules-based extractor pulls fields with a confidence score and evidence snippet for each.

Evaluate

Assess fit before review

Fit score + eligibility (incl. fiscal sponsorship) computed at stage time; the queue ranks strong eligible matches first and flags what's closing soon — green, never alarm-red.

Report

Brief the user

A weekly digest, Act-Now first, honest about unverified fields — from the same DB state, in the UI or the CLI. Read-only: it never changes a candidate.
